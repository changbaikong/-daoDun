## 当前首页背景

现在首页用的是一张蓝发少女插画（用户提供），已处理成两张：

| 文件 | 实际尺寸 | 说明 |
| --- | --- | --- |
| `web/assets/hero-bg.jpg` | 1672 × 941（16:9） | 桌面背景，JPG quality 88，约 113KB |
| `web/assets/hero-bg-mobile.jpg` | 1080 × 1920（9:16） | 从同一张图以人物脸部为中心裁切，JPG quality 86，约 157KB |

- 源图分辨率 1672 × 941，在 1080p 屏幕上够用；在 2K/4K 屏幕上会被放大，**如果能拿到 2560 × 1440 或更高的原图，直接覆盖 `hero-bg.jpg` 效果更好**。
- 桌面端背景用 `background-position: left center` 定位：人物会落在偏右位置，左侧文案区叠加深色渐变遮罩，避免文字压脸。
- 手机端背景是按人物脸部居中的 9:16 裁切；竖屏下文字整体靠底部排列，脸部保持在屏幕上方可见区域。
- 不再使用看板娘独立立绘；看板娘以文字问候的形式出现。

## 页面怎么用这两张背景图

- 桌面背景铺满整个首屏：`background-size: cover; background-position: left center;`
  比例不完全一致也不会破版，**超出的部分会被裁掉**，所以「主体放中间偏右」最安全。
- 屏幕宽高比小于 4:5（手机竖屏）时，CSS 自动切换到 `hero-bg-mobile.jpg`。
- 页面在背景上叠了两层深色渐变：左侧一层横向遮罩保证文案可读，一层纵向描边压暗上下边缘；所以背景可以偏亮、偏繁复，不用自己先把左侧压黑。
- 首页目前**不使用立绘**（已按需求移除 AI 生成的占位立绘），文字内容在左侧；以后要加立绘时，规格见下方「看板娘立绘」，并需要恢复 hero 右侧的立绘位。

## 桌面背景（hero-bg.jpg）

- **推荐 2560 × 1440**：在 2K 竖屏/笔记本视网膜屏上保持清晰；在 1080p 屏幕上也会被缩放，不浪费。
- **最低 1920 × 1080**。**4K 屏**如果很在意细节可以用 3840 × 2160，但文件会大不少，通常 2560 × 1440 已经够。
- **超宽屏（21:9，如 3440 × 1440）**：不要专门为它做图。`cover` 会把 16:9 图上下裁一点，或者左右补黑边；把视觉主体放在**中间 16:9 区域**即可。
- 构图建议：
  - 视觉主体（人物、月亮、建筑）放在**中间偏右**，因为左侧要放标题和按钮；
  - 左侧 40% 尽量干净、低对比，避免和文字打架；
  - 不要把重要内容放在四边 10% 以内（不同屏幕会被裁）；
  - 不要在背景里烘焙文字或 UI。
- 文件：
  - 格式：JPG（quality 82–88）或 WebP（quality 80–85）；
  - 体积：建议 **≤ 600KB**（占位图约 84KB）；
  - 色彩：sRGB，不要 CMYK；导出时去掉 EXIF，避免设备色彩偏移；
  - 命名：`hero-bg.jpg`，直接覆盖同名文件即可生效（浏览器缓存的话 Ctrl+F5）。

## 手机竖屏背景（hero-bg-mobile.jpg）

- **1080 × 1920（9:16）**，JPG / WebP，建议 ≤ 500KB。
- 页面在手机上的实际布局是：标题 → 按钮 → 统计（自上而下），所以竖版背景的**中上部**可以放视觉主体（月亮、云、远景），**底部**留给深色渐变/山影，衬托文字。
- 如果暂时不想做第二张：只放 16:9 的桌面图也能用，`cover` 会裁掉左右两侧，主体居中即可；但竖屏构图会显得比较空。

## 看板娘立绘（可选，当前未使用）

- **推荐 1200 × 1600（3:4）**，透明背景 PNG；
  - 追求更细腻可以画 **2400 × 3200** 再缩到 1200 × 1600 导出，边缘更干净；
  - 文件建议 ≤ 800KB；如果更大，可以转 WebP（同样支持透明）。
- 脚下留 **5%–8% 的透明边距**，避免鞋子贴边被裁。
- **不要带背景、不要带文字**；投影/光晕/漂浮动画建议交给 CSS，图片只保留角色和必要的小装饰（星光、发饰）。
- 朝向：建议**面朝左**或半侧身朝左。页面文字在左、角色在右，朝左会更有「迎向读者」的感觉。
- 如果立绘是全身像：3:4 画布、人物占画布高度的 90% 左右比较合适；如果是半身像，可以在 3:4 画布里居中偏上，让底部自然留白。
- 目前首页已移除立绘；以后要放回时，准备好图片后需要恢复 hero 右侧的立绘位（HTML/CSS 改动，随时可以让我加回来），再 Ctrl+F5 刷新。

## 文章页顶部横图（articles-hero.jpg）

第二页 `/articles` 顶部用一张独立的横图，**不复用首页背景**：图片铺满顶部横幅，标题和数据叠在底部深色渐变上，图片下方是整块不透明的文章列表。

| 文件 | 实际尺寸 | 说明 |
| --- | --- | --- |
| `web/assets/articles-hero.jpg` | 1280 × 720（16:9） | 白发少女插画（用户提供），JPG，约 106KB |

- 显示尺寸由 CSS 控制：高度 `clamp(300px, 46vh, 460px)`，`object-fit: cover` + `object-position: center 10%`；所以**人物头部靠上**的构图最合适，超宽屏会左右裁切，重要内容放中间即可。
- 左侧约 40% 会叠横向深色渐变来衬托「文章」标题，主体放中间偏右、左侧尽量干净。
- 换图直接覆盖同名文件即可，不需要改代码。

## 占位素材

如果临时需要一张纯星空占位背景，可以运行：

```powershell
npm run assets
```

它会用 Python + Pillow 在 `web/assets/placeholders/` 下生成两张占位图（**不会覆盖** `hero-bg.jpg` 等正式背景），需要时手动复制改名过去即可。

## 验收清单

- [ ] 桌面背景 16:9，宽 ≥ 1920（推荐 2560 × 1440）
- [ ] 手机背景 9:16，1080 × 1920（可选）
- [ ] 背景主体在中间偏右，左侧 40% 低对比、无文字
- [ ] 背景四边各留 ≥ 10% 安全边距
- [ ] JPG 质量 82–88 / WebP 80–85，桌面 ≤ 600KB，手机 ≤ 500KB
- [ ] sRGB，去掉 EXIF
- [ ] 首页立绘位保持移除状态（如需加回，另按上面的可选规格准备）
- [ ] 替换后强制刷新，手机和桌面各看一遍
